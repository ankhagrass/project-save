What your backup folder will look like

Your project files go inside current/, with the same relative folder structure. The folder you choose is the container for the whole backup.

Your chosen backup folder/
├─ current/          Your project folders and files
├─ .project-save/    Backup records and recovery information
└─ history/          Previous versions, created as needed

Keep these folders together. Some new file copies may also be stored inside .project-save/ when an older file or folder blocks their usual location. Nothing already backed up is moved or automatically deleted.

Skipped items are not copied, and older files may remain. To recover the complete saved file set in its original structure, use Restore into a new, empty folder rather than copying current/ alone.

For remembered folders, use these reconnect buttons before starting. Each button requests one permission directly from your click; other actions never open extra permission prompts.

Privacy, exclusions, and what to expect

Your file contents move between the folders you choose. This application has no upload endpoint, analytics, third-party scripts, or remote processing. Its content security policy blocks application network connections. The host still receives ordinary requests to load this website.

Some common secret files are excluded by name; other secrets will be copied. This is not a secret scanner. Generated folder names, private-key extensions, and local databases are also skipped by default; that can exclude real work such as Keynote .key documents or a build/ folder. Preview shows a prominent skipped count and the exact paths. Deliberate include overrides are available above.

Replaced versions are preserved as verified .tar.gz archives. Deleted source files can remain in both current copies and history, unencrypted. Nothing is automatically purged. To remove accidentally backed-up private content, stop all writers and manually remove the entire dedicated backup set, then rebuild a clean backup in a new empty folder. This intentionally loses all old checkpoints and is not a guarantee of secure erasure from an SSD, filesystem journal, or other copies. See the README for the procedure.

Unreadable source items produce an incomplete-backup report; readable files are retained, and previous entries for failed paths are kept where available. Stop other writers before retrying an interrupted run. An on-drive heartbeat lease helps detect another writer, but browser file APIs cannot provide an atomic cross-browser lock. Use one browser/profile per backup destination.

Keep this page open during operations and avoid editing files while backing up. Browser-only backups do not run with the page closed. Reconnect missing drives before retrying. Browser data clearing can remove remembered pairs, but it does not delete your backup; choose that backup folder to restore it.

Use a separate drive for an independent copy. Backups and history archives are not encrypted. Browser permissions cannot identify a physical drive by serial number; stored directory handles and backup identity markers guard against mixing saved projects. The public app must use a dedicated origin; another app on that same origin could access its saved folder handles.

Experimental preview. Tested with synthetic folders; not independently human-audited. Keep another backup of important work.
